# 货代获客工具 V1 开发实施计划

> 本计划从“技术方案评审通过”开始执行；当前提交不包含正式 V1 业务代码。

## 1. 里程碑

| 阶段 | 目标 | 主要产物 | 退出标准 |
| --- | --- | --- | --- |
| M0 发现方案验证（3～5 人日） | 验证潜客能否真实找到 | ADR、搜索词样本、Provider spike、同行/货主数据漏斗 | 每类至少跑通一批真实候选并得到可用潜客 |
| M1 核心事实库（6～9 人日） | 建立正确的数据所有权 | Product、Prospect、Role、Contact、ContactPoint、Evidence | 唯一约束、来源、基础校验、实体合并测试通过 |
| M2 产品池与匹配（6～8 人日） | 跑通企业复用和库存 | ProductMatch、ProductProspect、双角色库存、推荐理由 | VE/KR 复用验收通过，库存口径一致 |
| M3 补客流水线（8～12 人日） | 企业库优先、外部增量 | Provider contract、AcquisitionRun/Batch、Celery 编排、漏斗 | 幂等、重试、限流、停止条件和任务进度通过 |
| M4 触达闭环（5～7 人日） | 业务员可连续开发 | 列表/详情、复制、邮件、6 类结果、跟进、两级拒绝 | 所有结果副作用与产品语境测试通过 |
| M5 试用与上线准备（3～5 人日） | 用真实业务验证完整漏斗 | 种子产品、试用数据、监控、运行手册 | 同行/货主主链路通过，产出率和单客成本可观察 |

单人串行约 31～46 人日；2 名前后端并行并有数据/测试支持时，建议 5～7 周。真实 Provider 合规/采购等待不计入纯开发工期，是进度最大外部变量。

## 2. 交付顺序与依赖

```text
M0 契约/验证
  ├─ M1 企业事实库 ── M2 匹配与产品池 ── M4 触达闭环
  └─ Provider spike ─ M3 补客流水线 ───────┘
                                      ↓
                                M5 试用上线
```

先做事实库和一条端到端竖切，避免先造大规模爬虫后发现数据无法去重、解释或入池。

## 3. 工作分解

### M0：技术方案确认

- 确认租户/owner 模型、MySQL 版本、Alembic 基线、数据保留策略。
- 将本文 API 表扩为 OpenAPI 契约；确认分页、错误码、幂等键。
- 先以委内瑞拉海运和韩国海运生成同行/出口货主 SearchPlan，人工评审 Query 是否符合已确认规则。
- 用至少 1 个 Web Search、1 个官网 Enrichment、1 个 B2B/展会来源做小样本 spike，分别记录发现→去重→准入→联系方式→可用潜客漏斗。
- 验证城市展开、目的国/区域同义词、排除词、官网高价值页面和联系方式提取策略。
- 评审并冻结 ERD、Search Strategy v1、匹配规则版本、run 状态机、批次规模与停止条件。

### M1：产品与企业事实库

- 建表与数据库版本脚本；Repository/Service/API。
- 国家字典与物流产品表单（只含已确认字段）。
- Prospect 多角色、Contact/ContactPoint、Evidence CRUD/查询。
- 联系方式标准化和基础质量校验。
- 企业 identity、确定性合并、模糊候选与 merge log。
- 企业库搜索和企业详情页。

### M2：匹配、推荐与产品池

- 同行/出口货主准入规则分别实现。
- 解释性 relevance band 与 recommendation reasons。
- ProductMatch 重算事件和版本化。
- ProductProspect 唯一约束、入池服务、目标库存与统计查询。
- 企业库强/中候选、其他合格候选的消费顺序。
- VE/KR Evidence 复用端到端测试。

### M3：Discovery / Enrichment

- Provider contract、注册表、配额、超时、重试、熔断。
- AcquisitionRun/Batch 状态机：queued/running/completed/partial/failed/cancelled。
- Query Generator：国家/区域/运输方式同义词、城市展开、基础同行词、产品相关词、来源限定、排除词。
- 同行发现：基础覆盖 Query + 产品相关 Query；企业国际货运资格识别；庄家信号只降序。
- 出口货主发现：B2B 中国供应商 + 出口展会 + 官网公开网络；出口证据准入与目的国排序分离。
- Website Enrichment：主页、Contact、About、Products、Market/Global/Export、Team 的限量抓取与 Evidence/Contact 提取。
- 批量实体解析、Qualification、完整富化、联系方式补全、验证、全局 upsert、全产品重算、当前池入池。
- 用最近产出率估算候选预算；实现按批执行、连续空批/查询耗尽/成本上限/库存达标等停止条件。
- 进度查询、停止原因、每个 Query/Provider 漏斗与错误诊断。

### M4：触达与跟进

- 潜客表格、角色切换、推荐理由与来源、企业详情抽屉。
- 电话/邮箱复制；现有邮件服务适配 ContactPoint 和产品语境。
- ContactActivity 写入与历史；6 类结果。
- 联系方式无效只更新具体点位；“近期有货”等生成有时效的 sales_verified Evidence。
- 产品 suppression 与企业 global DNC 明确选择。
- 下次跟进时间、备注、提醒查询；不扩展 Opportunity/Quote/Order。

### M5：真实试用与上线准备

- 建立委内瑞拉、韩国两个种子物流产品，同行与出口货主分别执行真实补客。
- 人工抽检企业真实性、角色判断、Evidence 来源、联系方式和推荐理由。
- 观察每个 Query group / Provider 的发现量、去重率、准入率、联系方式覆盖率、最终可用率和单客成本。
- 验证韩国发现的新企业能通过 VE Evidence 反向增强委内瑞拉候选，且不自动塞入旧产品池。
- 删除低产出 Query、调整批次与停止阈值；形成上线默认 Search Strategy v1 和运行手册。

## 4. 测试计划

| 层级 | 必测内容 |
| --- | --- |
| 单元 | 角色准入、Evidence 新鲜度、推荐解释、库存、6 结果、副作用、DNC、标准化 |
| Contract | 每个 Provider 的输入/输出/错误/限流；API schema 向后兼容 |
| 集成 | 幂等 upsert、实体合并、任务重试、邮件活动关联、跨产品重算 |
| E2E | 创建产品、双角色库存、补充、列表、详情、触达、跟进、复用 |
| 发现质量 | Query 样本、企业真实性抽检、Evidence 来源、联系方式有效率、单客成本 |
| 性能 | 10 万/100 万 Prospect 量级的列表、匹配重算、批量入池和索引计划 |

## 5. 发布门禁

- 任何可用潜客必须有角色准入证据与至少一个通过基础校验的 ContactPoint。
- 推荐理由可追到 Evidence/source_url；不返回孤立 match score。
- 重放同一 Provider 批次不产生重复企业、联系方式、Evidence 或入池关系。
- 调低库存不删除任何企业、关系和历史。
- 产品已满时新增优质候选只留在 ProductMatch；不会偷偷替换工作集。
- 产品级拒绝不影响其他产品；全局拒绝阻止所有主动触达。
- V0 代码未被删除或破坏；V1 不依赖任何 V0 业务数据即可独立运行。

## 6. 人员分工建议

- 产品/业务负责人：验收推荐解释、6 类结果、库存口径和 Provider 样本质量。
- 后端：事实库、匹配/池、活动、API、异步编排。
- 前端：产品工作台、列表/详情、交互、进度与异常状态。
- 数据/后端兼任：Provider spike、实体解析、漏斗。
- 测试：从 M0 参与真实搜索样本，重点覆盖发现质量、重复、幂等和跨产品副作用。

## 7. 不纳入 V1 首批

微信/WhatsApp/拜访、系统内拨号、完整 CRM/商机/报价/订单、自动淘汰低质量未触达潜客、用户自定义关键词/排除词/数据源、黑盒 0～100 分、贸易/海关数据强依赖、通用行业 UI、自动持续搜索。新增范围必须走变更评审，不能挤占上述主链路。
