### 从代码还原的产品定位

这是围绕公司级潜在客户展开的货代获客与轻量业务管理工具。客户模型明确包含其他货运公司、物流公司；业务员端的发现客户默认关键词是 freight forwarder，国家选择集中在非洲。AI 潜客模块的国家、行业与客户画像为自由输入，因此并非只能保存货代同行。[S01–S03]

> 现状不是一条统一的“自动找客户 → AI 判断价值 → 自动成交”流程，而是“采集线索 → 人审 → CRM”与“人工提供潜客 → 背调/话术 → 跟进”两条并行链路。

| 关键结论 | 代码中的实际含义 |
| --- | --- |
| 确有搜索采集能力 | 数据采集通过 Google 搜索、限定站点搜索和给定网页采集产生待审核记录；不等于已经验证的客户。 |
| “AI 获客任务”不是搜索引擎 | 执行器仅处理用户输入的官网列表；产品词、排除词没有用于搜索或筛选；自动建档匹配分固定为 60。 |
| 线索分数不等于购买意向 | 可信度分主要是来源与原始字段是否存在的加分；重复分 70 是标记；背调中的需求信号可能来自通用规则文案。 |
| 完成度不能按页面数量判断 | 已发现 CSV 路由缺失、业务员发现入口权限冲突、智能体话术调用错误、本地自动化配置未接调度等问题。 |

### 权限规则 R-ROLE-01～06

R-ROLE-01：登录用户必须存在且处于启用状态；访问接口使用 Bearer 访问令牌。R-ROLE-02：采集任务与采集线索的业务操作要求管理员。R-ROLE-03：AI 任务、潜客、报告、话术、联系人通过所属潜客校验当前用户；管理员在这些接口中也按本人处理。[S04、S05、S08]

R-ROLE-04：普通 CRM 详情/修改接口要求客户属于本人；普通任务详情/修改/完成要求任务分配给本人。R-ROLE-05：客户和普通任务删除要求管理员；用户删除要求管理员且不能删除自己。R-ROLE-06：邮件列表与详情按发送用户隔离，通知查询与已读/删除按接收用户处理。[S15、S17、S20、S21]

### 不得误写成业务授权的实现缺口

CRM 带 search 的列表丢失归属筛选；“未分配”接口实际未加空归属条件；领取接口可覆盖原负责人；导出未按用户隔离。公开注册接受 admin 角色、钱包调整允许普通登录用户操作本人余额、WebSocket 直接接受路径 user_id。这些属于权限/契约问题，不还原成合理的“全员可见”“自由加分”等产品规则。[S04、S15、S21、S24、S26]

系统没有独立的企业租户、部门资源隔离或自定义角色权限模型。用户的 department 是资料字段，不能等同于部门级权限体系。前端双端路由守卫主要判断登录状态，业务权限以服务端为准。[S01、S04]

## 04 总业务流程与状态模型

### 流程 A：通过公开网页采集，进入 CRM

> 管理员创建采集任务 → 启动搜索/网页采集 → 标准化并写入 ScrapedLead（pending）→ 人工通过或拒绝 → 对 approved 线索执行导入 → 与 Customer 查重 → 新建未分配客户 → 领取/分配 → 联系与合作状态维护。

这一流程不自动生成企业背调，也不自动转为 AI 模块的 Lead。采集得到的联系方式属于采集线索/CRM 字段，不会自动变成 LeadContact。[S05–S08、S15]

### 流程 B：已有公司或网址，进入 AI 辅助开发

> 用户手动新增 Lead，或提供官网列表运行 AI 任务 → 可选生成企业背调 → 可选生成渠道话术 → 人工维护联系人与内容 → 单次邮件发送或创建跟进 → 邮件渠道到期发送；其他渠道人工处理 → 用户维护潜客状态。

背调、话术、联系人与发送不是强制逐级审批：可以不背调直接生成话术，也可以直接输入收件人和正文发信。未发现 Lead → Customer 的已注册转换接口或自动同步调用。[S08–S14]

| 对象 | 代码中的状态 | 实际转换约束 |
| --- | --- | --- |
| 采集任务 | pending / running / completed / failed / cancelled | 启动要求 pending；取消只更新状态，后台可能继续并覆盖为 completed。 |
| 采集线索 | pending / approved / rejected / imported | 仅 pending 可审核；仅 approved 可导入；重复项通常保留 approved；导入项禁止删除。 |
| AI 获客任务 | pending / running / completed / failed / cancelled | 运行接口先写 running，允许再次运行；并非严密的单次执行状态机。 |
| AI 潜客 | new / researched / copy_generated / contacted / replied / invalid | 操作会覆盖状态；更新接口允许枚举值修改，不是不可逆漏斗。 |
| 潜客跟进 | pending / completed / failed / cancelled | completed 不可改回；failed 可重试并设到期时间为现在。 |
| CRM 客户 | potential / contacting / cooperating / paused / lost | 不同更新接口约束不一致；非强制线性流转。 |
| 普通待办 | pending / in_progress / completed / cancelled | 与采集任务、AI 搜索任务、潜客跟进任务分属不同模型。 |

“发现数”“已保存数”“潜客数”“客户数”“跟进完成数”统计的是不同对象；不能直接串成统一的获客转化率。[S06、S14、S15、S20]

## 05 客户发现：任务输入与执行

### R-DISC-01：创建与启动采集任务

任务包含名称、类型、关键词列表、国家列表、指定来源 URL、配置参数与创建人。服务端先保存 pending；启动时清空本次进度、错误与日志，写 running 并提交，然后在 Web 进程中通过 asyncio.create_task 启动独立会话执行采集，不是该模块使用 Celery 队列。[S05、S06]

| 输入 | 页面/接口表达 | 真正的执行影响 |
| --- | --- | --- |
| task_type | google、目录类、specific_site、port_authorities 等 | 决定搜索词构造与采集分支；部分旧别名会归一化。 |
| keywords | 业务员默认 freight forwarder | 实际参与 Google 查询；不是 AI 产品关键词字段。 |
| countries | 业务员可选 NG/ZA/EG/KE/MA/GH/ET/TZ | 参与搜索词或站点选择；不构成目标企业所在国的事实验证。 |
| source_urls | 提供待抓取页面 | 规范化后逐个抓取；一次 URL 抽取一条公司记录，不遍历目录中所有企业。 |
| business_type | 业务员表单：sea/air/land/multimodal | 传入配置，但当前 Google 主链未按其筛选或分类公司。 |
| max_results | 业务员默认 50，可选 10～500 | 外层执行器读取的是 max_results_per_keyword，不能把表单值当成最终返回总上限。 |
| max_results_per_keyword | 执行器配置，缺省 5 | 作为每关键词请求规模；后续还有国家/关键词/查询数截断，没有统一的最终公司去重上限。 |
| API 凭据 | Google API key + 搜索引擎 ID | 两者同时存在使用搜索 API；否则尝试解析 Google 搜索结果 HTML。 |

### R-DISC-02：监控、结果与取消

执行器记录 progress_current、progress_total、status_message、execution_log、last_run_summary、错误及起止时间；日志仅保留最近 80 项。total_found 为本次原始结果数，total_saved 为本次保存记录数，不是独立公司的数量。空结果可正常 completed，并提供诊断信息。[S06]

取消要求 pending/running，但仅修改数据库状态，没有取消已创建的 asyncio 任务，也未在主循环中阻止后续写入；完成回写可能覆盖取消状态。Web 进程退出后的续跑、持久队列重试和完整去重恢复，不能视为本模块已实现。[S06]

## 06 客户发现：搜索与采集方法

### R-DISC-03：Google 搜索

查询由关键词与国家组合，形式为“关键词 in 国家”。GoogleSearchScraper 内部只取前 5 个国家与前 3 个关键词构造组合；API 分支最多处理前 10 条查询，每条 num 不超过 10，未做搜索结果翻页；HTML 分支最多处理前 5 条查询，依赖 div.g、h3 等页面结构解析。[S07]

拿到搜索结果后，程序再请求结果网站。公司名称优先取网页 og:title，其次搜索标题清理结果，再尝试 h1；邮箱优先 mailto 链接，再用页面正则；电话优先 tel 链接，再尝试文本。没有找到联系人姓名、职务和邮箱真实性核验的流程。搜索或网站请求异常可被记录后跳过，因此“任务完成”并不代表每个网站都成功。[S07]

该路径国家识别主要看网址域名后缀，内置映射包含 .ng/.za/.eg/.ke/.ma/.gh/.et/.tz/.ci/.sn。使用 .com 的公司即使由某国关键词搜出，也不能据此自动获得已核实的国家；后续可能进入 Unknown/XX。[S07、S09]

### R-DISC-04：商业目录与港口来源

目录类不是直接调用 Kompass、黄页的企业数据 API，而是构造 site:域名 限定词，再调用同一 Google 搜索能力。站点映射包括尼日利亚 businesslist.com.ng/finelib.com、肯尼亚 businesslist.co.ke/yellowpageskenya.com、南非 brabys.com/yellosa.co.za、加纳 businessghana.com/ghanayello.com、埃及 egyptyello.com/yellowpages.com.eg。[S06]

来源关键词构造最多取前 6 个站点并将组合截为 12 条；目录关键词构造还会取前 4 个站点并截为 12 条；随后 Google 再截前 3 个关键词。不同上限叠加，不能理解为遍历所有国家和全部目录。某些目录分支还可能叠加多个 site: 条件。[S06、S07]

### R-DISC-05：指定网页采集

specific_site/port_authorities 分支实际上仍先执行搜索，再处理给定 URL；其他采集分支也可在搜索后处理给定 URL。网页采集只读当前页面，不遍历企业详情链接；去除脚本等标签后，取 h1/标题推断公司名称，用文本正则取邮箱、电话，保留最多 500 字简介。国家按用户提供的第一个国家赋值，不由地址智能识别。[S06]

> 指定目录页可能被当成“一家公司”；高匹配的搜索词不等于目标公司真实业务匹配。以上是当前算法边界，不是采集效果承诺。
