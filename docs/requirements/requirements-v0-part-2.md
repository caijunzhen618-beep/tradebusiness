## 07 线索分析：清洗与可信度

### R-QUAL-01：写入待审核线索前的标准化

| 字段 | 当前规则 | 含义与限制 |
| --- | --- | --- |
| 公司名称 | 依次取 company_name/name/title/organization；有效字符串长度 >2，否则 Unknown Company | 缺失名称不会触发整条拒绝。 |
| 国家与代码 | 有代码则转大写；内置标准化映射覆盖 NG/KE/ZA/GH/EG/US；未知时可能为 Unknown/XX | 与搜索器的国家映射不是同一套，不能假设所有非洲国家都同等标准化。 |
| 邮箱 | 去首尾空格、转小写、正则检验，不合格置空 | 只是字符串格式检查；不是邮箱可投递性或所有权验证。 |
| 电话 | 保留数字和 +，长度至少 7 | 没有运营商、国家号真实性或 WhatsApp 注册核验。 |
| 官网 | 缺少 http 开头时补 https:// | 不是完整域名归并；http/https、子域或路径仍可能重复。 |
| 简介与来源 | 简介长度 >10 才保留，最多 500；来源 URL 从 source_url/url 获取 | Google 结果未必填 source_url；原始 JSON 与官网仍有价值，但字段级来源可能缺失。 |

### R-QUAL-02：confidence_score 的真实公式

> 可信度 = min(100, 50 + 来源加分 + 原始邮箱存在×10 + 原始官网存在×10 + 原始电话存在×10)。

来源加分仅对精确类型 google＝20、directory＝15、specific_site＝25 生效；kompass、yellow_pages、port_authorities 等其他类型若未映射为上述名称，则来源加分为 0。分数根据原始字段计算，可能发生“原始邮箱存在而加分，但标准化后邮箱被置空”。没有看到按该分数自动通过审核或拒绝入库的阈值。[S09]

### 业务解释示例（演算，不是真实采集结果）

一条 google 线索同时有邮箱、官网、电话，得分为 100；这只说明命中该规则的来源和字段条件，不能说明它一定有中国出口运输需求、有采购预算或愿意合作。一条 kompass 线索拥有同样三个字段，得分可能只有 80，差异来自来源命名，不是企业商业价值更低。[S09]

raw_data 保存采集输入、confidence_score 保存规则结果，审核状态单独保存。分数、事实、人工结论是三类不同数据。当前采集入库主链未调用模糊重复检测工具，也未在保存前按公司唯一性去重。[S06、S09、S10]

## 08 采集线索审核与客户导入

### R-REVIEW-01～03：审核与删除

管理员可按状态、来源、国家代码、采集任务筛选并查看明细/统计。只有 pending 可以 approved 或 rejected；记录审核人、审核时间及可选拒绝原因。批量操作逐项处理，缺失或状态不符计入错误。实际服务禁止删除 imported，其他状态可删除；接口注释“仅拒绝或已导入可删”与执行代码相反，以服务逻辑为现状。[S08、S10]

### R-IMPORT-01：仅导入 approved

导入服务跳过未通过状态，先对 Customer 查重。检测到重复时计入 duplicate_count，写 duplicate_of 为现有客户 ID、similarity_score 为固定 70，通常保持 approved 而不导入、不自动合并。无重复则建立 Customer，并记录 imported_to_customer_id、imported_at、matched_by，将状态改为 imported。[S10、S11]

> 实际重复条件：有邮箱时，“公司名完全相同 AND 邮箱完全相同”；没有邮箱时，只检查“公司名完全相同”。不是任一字段相同即重复，也不是相似度达到 70%。

独立 DuplicateDetector 中存在名称/邮箱/网址/电话的加权比较与 70 阈值，但已追踪的采集保存、审核和正常导入流程没有调用它。导入 API 中的 70 是重复标记值，不是该工具计算结果。导入器内部另有“合并来源/标签”的分支，但正常服务先跳过重复记录，不能把这段孤立分支描述成用户已可用的自动合并功能。[S09–S11]

| 来源/目标 | 实际转换 | 注意事项 |
| --- | --- | --- |
| 公司、国家、联系方式 | 复制公司名、国家/代码、城市、邮箱、电话、WhatsApp、官网等 | 不是新一轮事实核验。 |
| 业务类型与简介 | 正常导入字段映射未复制这两项 | 采集阶段有内容，CRM 中仍可能丢失。 |
| 客户状态/归属/优先级 | potential / assigned_to=None / priority=3 | 通过审核不等于联系过或已合作；需要后续领取/分配。 |
| 来源与质量 | source 为“数据采集: 类型”；复制 source_url 与 confidence_score | data_confidence 沿用规则分，不升级为经人工证实的数据。 |
| 标签与追溯 | scraped 标签、来源类型标签；备注含来源、采集时间、任务 | duplicate_of 字段注释指向采集线索，但实际服务写入的是 Customer ID。 |

CRM 手工创建另有“邮箱重复或公司名重复即拒绝”的规则，与采集导入的 AND 条件不同；两条入库路径可能产生不同的重复判断。[S11、S15]

## 09 AI 获客任务与潜客建档

### R-AILEAD-01：创建个人获客任务

用户输入任务名（必填）、目标国家、目标行业、产品词、客户画像、排除词及官网列表；数组以 JSON items 结构存储。官网缺协议时补 https://，去尾部斜杠。任务归当前用户所有，列表可按状态筛选。仅任务名称必填，允许没有官网的任务存在。[S12、S13]

| 输入/行为 | 代码实际处理 | 实现判定 |
| --- | --- | --- |
| 官网列表 | 逐项创建潜客；同用户、同任务、规范化后同网站跳过 | A：网址批量建档；不是跨任务全局查重。 |
| 公司名称 | 从域名首段去 www、替换连字符/下划线等并标题化 | B：名称猜测，不读取官网核实法定或品牌名称。 |
| 国家 / 行业 / 画像 | 直接复制为 Lead.country / industry / description | A：保存用户假设；不是搜索发现的企业事实。 |
| 来源 / 匹配分 | source=manual_website；match_score=60 | C：固定分数，不是 AI 匹配算法。 |
| 产品词 / 排除词 | 存储但未用于执行搜索、过滤或评分 | C：只有参数，没有相应发现逻辑。 |
| 空官网 / 重复运行 | 空列表可 completed 且新增 0；重复运行统计本次新增，可能变成 0 | A/B：不能用 total_found 代替该任务累计潜客总量。 |

### R-AILEAD-02：运行与取消

运行接口先写 running 并提交，再发布 Celery 任务；发布异常才同步回退。发布成功但没有 Worker 消费，不会触发该回退。服务内部会在处理网址时检查取消，但 API 的 run 先覆盖状态，不能视为严格禁止重跑或取消后重启；并发和持久化效果未运行验证。[S12、S14]

### R-AILEAD-03：独立潜客维护

支持手动新增、按任务/状态/关键字分页查询、详情及字段/状态更新。手动新增未复用任务运行的同站点去重逻辑；用户也可手动填写或修改 0～100 的匹配分。潜客状态修改只校验枚举值，没有商业阶段的前置条件。[S12、S13]

CSV 导入在管理端有按钮并请求 POST /api/v1/lead-generation/leads/import，但该后端模块没有注册对应导入路由，不能记为可用功能。采集线索导入 CRM 则是另一套已存在的接口。[S08、S13、S29]

## 10 企业背调的具体业务逻辑

### R-RESEARCH-01：触发与输入

用户选择自己拥有的 Lead 发起背调。先查该潜客最新报告：已有报告直接返回，不重新抓取、不重新生成、不重复扣费。无报告时先执行 5 积分扣减，再读取官网并生成、保存报告，最后将潜客状态写为 researched。[S16、S24]

官网抓取仅当前单页：HTTP(S) 公网页面，校验私有地址等风险，超时 12 秒、最大 2MB、要求 HTML，不跟随重定向；去除脚本/样式等，文本最多保留 12,000 字符。抓取失败返回空文本而非必然中断报告。发送给模型的官网文本实际又截为前 1,000 字符，没有遍历 About/Contact 页面、JavaScript 渲染或跨站验证。[S16]

### R-RESEARCH-02：生成与回退

模型输入是公司名、国家、行业、官网、已有描述与官网截断文本。通过可配置的兼容 chat/completions 接口请求 JSON；HTTP 类错误按配置重试。配置为 rules/rule_based/mock、缺少 API Key、调用失败或结构不符合要求时，转为内置规则报告。主路径要求 summary/business_model/products 等基本键，但不是对每条业务断言做事实核验。[S16]

| 报告字段 | 向用户表达的内容 | 证据限制 |
| --- | --- | --- |
| summary / business_model | 公司概况与商业模式 | 模型或规则归纳，不等于工商认证。 |
| products / target_markets | 产品业务和目标市场 | 可能来自用户输入、片段文本或通用推断。 |
| buying_signals | 值得关注的需求信号 | 没有接入真实出货、询价、采购或预算事件。 |
| pain_points / recommended_angle | 可能痛点与开发切入点 | 建议性文案，不能当作对方已经表达的需求。 |
| raw_sources | 来源对象、generation_mode 等元信息 | 有元信息字段，但不是逐句证据链或多来源验证报告。 |

### R-RESEARCH-03：规则报告与保存结果

规则报告会围绕潜在采购/分销/供应商合作、成本、物流时效和沟通等生成通用描述，标记 generation_mode=rule_based_mvp，并记录是否取到官网文本。规则正常返回同样会被保存并计费；这不意味着已完成真人背调或真实 AI 搜索。[S16]

报告不会自动补齐联系人、验证邮箱或更新 match_score。潜客资料修改后仍复用旧报告；报告生成会覆盖 Lead.status，可能把已联系阶段改回 researched。当前没有显式的版本刷新/强制再背调入口或多轮事实更新机制。[S12、S16]

## 11 四类分析结果的正确解释

| 对象与字段 | 当前计算或来源 | 能说明什么 / 不能说明什么 |
| --- | --- | --- |
| ScrapedLead.confidence_score | 50 基础分 + 来源分 + 原始邮箱/官网/电话加分，封顶 100 | 可辅助看字段完整度；不能证明联系人有效、企业靠谱或有运输需求。 |
| ScrapedLead.similarity_score | 正常重复判断命中后写固定 70 | 表示命中了当前查重条件；不是 70% 相似，不是算法置信概率。 |
| DuplicateDetector 工具 | 名称、邮箱、网站、电话加权，提供阈值判断 | 工具函数存在，但未接入正常采集/审核/导入主链，不能宣称智能去重已生效。 |
| Lead.match_score | 官网任务创建固定 60；手工新增/编辑可提供 0～100 | 是默认/人工字段；不是按货代能力、航线或客户需求计算的匹配度。 |
| CompanyResearchReport | 已有资料 + 单页片段 + 模型或通用规则 | 提供开发参考文案；不是统一的线索价值评分模型，也不自动回写上述分数。 |

### 从“发现一家企业”到“判断它是不是客户”

当前代码实际完成的是搜索命中、网页信息抽取、格式清洗、人工审核、重复检查、建档，以及基于有限材料生成建议。是否经营目标航线、是否从中国进口、是否有代理合作需求、谁能决策、近期货量和预算如何，未见与这些问题对应的独立事实获取与判定流程。[S03、S06–S16]

### 端到端演示口径（虚构输入，解释代码，不代表实测）

例 A：搜索某非洲国家的 freight forwarder，找到一家 .com 网站并抽到邮箱、电话，原始规则分可到 100。但国家仍可能未知、邮箱仍可能无效；记录先进入待审核线索，人工批准后才可导入 CRM。导入时还会按公司名与邮箱的现行条件检查重复。

例 B：把同一公司的网址手动放入 AI 获客任务，得到的是独立的 Lead，名称按域名猜测、匹配分 60。系统不会自动找到例 A 的采集线索或 Customer，也不会合并联系人。发起背调时使用该 Lead 的资料和官网片段；未配置模型时仍能拿到规则报告，但它不提供额外的已证实商业信号。

> V0 的准确名称是“获客资料采集与开发辅助能力”，不能根据现有分数推导出“系统已自动识别高意向货主/同行”或“已形成客户成交预测”。

## 12 联系人、销售智能体与话术

### R-CONTACT-01：联系人

对自己拥有的 Lead 新增和查询联系人，可记录姓名、职务、邮箱、电话、LinkedIn、WhatsApp、来源和 is_verified。除关联潜客外，多数字段可空；邮箱字段本身是普通字符串，is_verified 可人工传入。没有调用外部寻人或联系人验证服务，不能把该标记理解为平台认证。[S12、S13]

### R-AGENT-01：销售资料、知识与提示模板

用户可配置智能体名称、公司介绍、产品介绍、价值主张、目标客户、语气、禁用词、默认语言和默认标记；上传/查看/删除知识资料，新增/查看智能体话术模板。知识上传直接按 UTF-8 解码、丢弃无法解码字节、最多保存 100,000 字符，并把 embedding_status 写成 ready；未执行 PDF/Word 正文解析或真正向量化。[S18]

知识 Repository 的检索是按公司名、国家、行业关键词在整篇文本中是否出现计数排序，再拼接最多 8,000 字符；提供给模型的知识又截为 2,000，模板截为 1,000。字段叫 embedding_status 不代表已经具备向量知识库。禁用词与默认语言也不能仅因存在字段就认定为已执行的硬性限制。[S16、S18]

### R-COPY-01：生成开发话术

基础路径：校验潜客归属 → 扣 2 积分 → 取已有背调摘要（可无）→ 取可选智能体/模板 → 生成并保存 SalesCopy → 写潜客状态 copy_generated。每次生成新记录并再次扣费，历史文案可查询。支持 email/whatsapp/linkedin，默认 en、professional；无需先有背调。[S16、S19、S24]

模型不可用时生成中文或英文固定结构文案；其他语言值并没有对应完整的规则多语种能力。WhatsApp 主要压缩段落，LinkedIn 使用连接邀请风格。生成话术不等于已经发送，也没有从“draft 文案”自动变为“sent 文案”的闭环。[S16、S19]

> 明确缺陷：SalesCopyService 将 get_context_text 调用到 SalesAgentRepository，但该方法定义在 KnowledgeDocumentRepository。选择有效智能体的分支会出现方法不存在问题；不能将“智能体知识生成话术”写成已可用。

上述调用错误以类定义与调用位置交叉核验；尚未运行复现。扣费代码在生成前执行，异常后的最终账务持久化取决于事务处理，本报告不把“先调用扣费”简单写成“失败必然扣款”。[S18、S19]
