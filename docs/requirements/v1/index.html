00 V1 核心方向

当前边界 国内货代在中国境内拓展客户，第一阶段目标是发现潜在客户企业并取得可触达联系方式。

核心链路：物流产品 → 企业发现 → 企业识别/去重 → 资格判断 → 完整富化 → 联系方式补全 → 数据校验 → 全局企业事实库 → 产品匹配 → 产品潜客池。

当前确认两类客户：国内同行货代与出口货主。搜索、爬虫、Provider、Evidence Extraction 等属于后台能力，不要求业务员配置技术参数。

01 物流产品

物流产品在获客系统中的作用是表达“我卖什么”，不是建立完整 TMS 产品模型。只优先结构化会影响“应该找谁”的字段。

字段类型说明
product_name文本展示名称，例如“委内瑞拉海派双清”；可由系统生成默认名称并允许修改
destination_countryCountry 字典核心获客特征，例如 VE
transport_mode枚举sea / air / rail / road / multimodal
description文本，可空双清、包税、到门、特殊能力等暂以描述承载
status枚举active / inactive

当前国内拓客默认起运国为中国。LCL/FCL、揽收范围、起运港/目的港、清关、派送、税费、特殊货等第一版不作为核心结构化搜索字段。

03 国内同行潜客发现

国内同行默认全国都可能成为客户，用户不需要选择深圳、广州等地区。系统内部可按城市拆分以提高覆盖率。

两类搜索同时执行

基础同行发现：国际货运代理、国际货代、国际物流、国际海运、freight forwarder 等，建立尽可能完整的同行候选池。

产品相关发现：例如委内瑞拉海运扩展 Venezuela、委内瑞拉、拉美、南美 + 货代/海运等查询。

目的国与运输方式用于扩展搜索和排序，不作为硬过滤。官网没写委内瑞拉的国际货代仍可能是客户。

同行排序

核心不是“同线路越强越好”，而是有货源能力 + 与我资源互补。相邻线路/区域相关是正向信号；明确同线路一手庄家、一级代理、全国收货等强供给方降低优先级但不删除。

04 国内出口货主发现

不从全国所有工厂无差别搜索，而优先从天然存在出口事实或出口意图的数据源建立候选池。

P0 来源：国际 B2B 中国供应商、出口型展会企业、企业官网与公开网络。

准入

明确出口事实或明显出口经营信号 + 可触达联系方式，才能进入出口货主可用潜客池。仅有英文公司名、位于外贸城市、产品看起来适合出口等弱推测不能单独准入。

产品相关性

目的国真实出口事实最强，其次为明确目的国市场关系、目的区域关系，再到有数据依据的主营产品/目的国需求关系。普通出口企业仍可保留。

贸易/海关数据价值很高，但不作为 V1 MVP 能工作的前置依赖。

06 数据源与潜客生产流水线

数据源分层

层级定位
P0搜索引擎、企业官网、公开企业/行业页面；出口货主再加国际 B2B、出口展会名单
P1更多企业/行业目录、联系人补全服务；由真实数据漏斗决定是否接入
P2贸易/海关数据，增强真实目的国贸易证据，不作为 MVP 前置依赖

一次发现，尽量完整富化

访问一个企业时，尽量一次提取所有公开且对未来获客有复用价值的信息：出口国家/区域、主营产品、业务线路、联系人、电话、邮箱及来源。

新数据反向增强旧产品

韩国获客新发现 D 企业，同时提取 Korea + Venezuela 市场事实后，D 也成为委内瑞拉产品的新匹配候选。不需要重新爬 D，也不自动强塞进所有产品池。

补充潜客顺序

① 企业库中新出现的强/中相关匹配 → ② 企业库其他合格候选 → ③ 仍不足才启动该产品增量外部发现。

新增企业完整富化后又会反向增强其他产品。系统使用越久，企业库复用率越高、重复数据获取成本越低。
