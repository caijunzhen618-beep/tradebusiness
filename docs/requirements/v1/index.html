00 核心边界

当前只服务国内货代在中国境内拓客，客户角色为国内同行货代与出口货主。用户表达“我卖什么、我要找哪类客户、希望保有多少待开发客户”；关键词、城市拆分、数据源与爬虫参数由系统承担。

物流产品 → 企业库优先匹配 → 不足时增量发现 → 企业识别/去重 → 资格判断 → 完整富化 → 联系方式补全与校验 → 全局企业事实库 → 全产品匹配 → 当前产品潜客池 → 电话/邮件触达 → 结果与跟进。

01 物流产品与目标待开发库存

产品核心字段product_name、destination_country、transport_mode、description、status；国内拓客起运国默认中国。
明确不提前结构化LCL/FCL、起运/目的港、揽收、清关、派送、税费、特殊货等；可先放名称或描述。
库存粒度产品 × 客户角色分别维护目标。
库存含义希望保持的“尚未首次触达、符合当前角色准入、可立即开发”的客户数，不是数据库容量。
调整规则调高/调低只改变缺口；不删除企业、产品关系或联系历史。

用户主动点击“补充潜客”，不做持续自动搜索。

02 Prospect / Contact / ContactPoint / Evidence

Prospect 是企业，全系统唯一且可多角色。同一家供应链企业可以同时是 freight_forwarder 和 exporter，企业主档与联系方式只保存一份。

Prospect ──< company_types
   ├──< Contact ──< ContactPoint (mobile / phone / email)
   └──< Evidence (企业级优先，保留来源与时间)

公司总机和通用邮箱可作为企业级 ContactPoint。格式校验与业务反馈分离；“联系方式无效”只标记本次使用的 ContactPoint，不判死企业。

Evidence 保存客观事实。为委内瑞拉发现企业时，如果官网同时披露 Venezuela、Korea、Japan，三项事实全部保存。

03 国内同行与出口货主发现

同行货代

全国发现；基础国际货代搜索与目的国/运输方式相关搜索同时执行。目的国不是硬过滤。排序重视“有货源能力 + 资源互补”；相邻区域正向，同线路一手庄家等强供给信号降序但不删除。

出口货主

从国际 B2B 中国供应商、出口型展会、官网等天然有出口事实/意图的来源开始。出口证据与可触达方式同时满足才准入。真实目的国出口、目的国市场、目的区域、有数据依据的品类关系依次增强排序；贸易/海关数据不是 MVP 前置。

04 Product Matching、ProductProspect 与跨产品复用

准入和排序分离，不向用户展示永久 0～100 黑盒分；展示“为什么推荐”并可查看 Evidence 来源。

一份全局企业事实库
    ├── Product Matching：可重算候选与理由
    └── ProductProspect：产品 × 企业 × 客户角色的实际工作集

补充顺序：① 强/中相关新匹配候选；② 企业库其他合格候选；③ 仍不足才外部增量发现。产品池已满时，新优质企业留作候选，不自动替换当前名单。

委内瑞拉 / 韩国复用：韩国产品发现 D 企业，同时取得 KR + VE 事实后，D 成为两个产品的匹配候选；韩国产品可按当前任务入池，委内瑞拉不自动入池，下次补充时优先消费。

05 电话、邮件、6 类结果与最小跟进

电话/手机/邮箱支持一键复制；Email 可复用系统发送能力。每次触达生成 ContactActivity，关联企业、产品、客户角色、联系人/联系方式、渠道和发生时间。

联系结果处理
未联系上保留，可再次联系
无该方向业务当前产品下暂不优先
有该方向业务，暂无货有效潜客，值得维护
近期有货 / 可以询价重点跟进，并形成有时效的销售确认 Evidence
联系方式无效只更新对应 ContactPoint
拒绝联系明确选择“当前产品”或“企业全局”范围

跟进仅保存可选下次时间与备注；不扩展完整 CRM、商机、报价、订单。

06 通用底座 + 货代策略

Prospect、Contact、ContactPoint、Evidence、实体解析、Provider、匹配、库存和活动尽量行业无关；LogisticsProduct、同行互补/庄家判断、出口市场解释属于货代策略。V1 用户界面仍只呈现货代业务语言，不变成通用获客配置平台。
