# V1-07 企业库、产品匹配与产品潜客池【已确认】

> 状态：已确认  
> 版本：V1

## 1. 一份企业库，不是每产品一张企业表

全系统维护共享企业事实库。不同物流产品通过关系引用企业，不复制 Prospect、Contact、ContactPoint。

## 2. 三层模型

### 企业事实库
回答：这家公司是谁、有什么客观业务事实、怎么联系？

### 产品匹配
回答：这家企业对于某个物流产品是否值得作为候选，以及为什么？

### 产品潜客池
回答：业务员当前针对该物流产品和客户角色实际准备处理哪些企业？它是业务工作集，不是独立企业数据库。

## 3. ProductProspect

```text
ProductProspect
- id
- product_id
- prospect_id
- customer_type       # freight_forwarder / exporter；同一企业可在不同角色池出现
- added_at
```

第一版不保存永久 Match Score。推荐理由通过企业事实、Evidence、联系方式和动态规则计算。

## 4. 企业库复用

为委内瑞拉产品发现 A 企业时，如果同时获得 VE / KR / JP 市场事实及联系人，后续韩国、日本产品直接复用这些企业数据，不重新抓基础信息。

## 5. 新企业反向增强旧产品

韩国产品搜索新发现 D，并提取到 Korea + Venezuela，则 D 同时成为委内瑞拉产品的新匹配候选。重新匹配不等于自动加入旧产品潜客池。

## 6. 目标库存 = 待开发客户库存

产品 × 客户角色分别维护目标库存。例如：

```text
委内瑞拉海派双清 · 同行货代
目标库存       500
待开发客户     220
已联系客户    1160
缺口           280
```

待开发客户指已经进入 ProductProspect、具备当前角色准入条件、且尚未在当前产品语境下完成首次触达的企业。

目标库存只是补充参考，不是容量上限。调低目标不删除任何企业或历史。

## 7. 补充客户顺序

用户主动点击“补充客户”后：
1. 计算目标库存与当前待开发客户的缺口；
2. 优先使用企业库中新出现且与该产品强/中相关的匹配候选；
3. 再使用企业库其他符合当前客户角色准入条件的候选；
4. 仍不足才启动当前产品增量外部发现；
5. 新发现企业完整富化后进入全局库，同时反向增强其他产品候选；
6. 达到目标库存或合理搜索空间耗尽后停止。

## 8. 产品池已满时的新优质候选

如果当前待开发库存已经达到目标，而企业库后来出现更高质量的新候选：
- 不自动删除/替换现有 ProductProspect；
- 不偷偷改变业务员正在处理的名单；
- 新企业保留为产品匹配候选；
- 用户下次需要补充客户时优先消费这些更高质量候选。

V1 第一版不做自动“淘汰低质量未触达客户”的复杂优化机制。

## 9. 企业多角色

同一 Prospect 可以同时是 freight_forwarder 与 exporter，因此同一企业可以在同一物流产品下分别符合同行池和出口货主池的业务语境。企业基础数据和联系方式共享，产品池关系按 customer_type 区分。

## 10. 数据资产效果

随着系统使用：企业库规模与 Evidence 增长，新产品直接命中率提高，老产品可消费其他产品搜索过程中新增的匹配企业，重复外部搜索和联系人获取成本下降。
