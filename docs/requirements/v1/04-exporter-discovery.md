# V1-04 国内出口货主发现【已确认】

> 状态：已确认  
> 版本：V1

## 1. 客户定义

第二类国内客户统一定义为 **出口货主 exporter**，不局限于法律或工商意义上的工厂。

出口货主可以包括工厂、工贸一体企业、外贸公司以及其他实际存在中国出口业务的企业。货代关心的是“企业是否有出口货物需要国际物流”，而不是企业是否登记为制造企业。

## 2. 发现原则

出口货主不从“全国所有工厂”无差别开始。系统优先从天然具有出口意图或出口事实的数据源建立候选池，再通过公开网络补充企业与联系方式。

第一版优先来源：
1. 国际 B2B 中国供应商/制造商
2. 出口型展会参展企业
3. 企业官网与公开网络
4. 其他能够证明出口经营的合法公开来源

贸易/海关数据属于高价值增强来源，但不作为 V1 MVP 能运行的前置依赖。

## 3. 出口货主准入规则

出口货主进入可用潜客池需要同时满足：

1. 存在可信的出口事实证据或明显出口经营信号；
2. 至少存在一种通过基础质量校验的可触达联系方式。

### 强出口证据示例
- 可靠贸易数据存在出口记录
- 国际 B2B 平台以中国 Supplier / Manufacturer 身份经营
- 出口型展会参展企业
- 官网明确说明 Export / Global Market / Overseas Market / 产品出口多个国家等

### 明显出口经营信号示例
- 海外营销网站/多语言站
- International Sales / Overseas Sales / Export Department
- `export@...` 等出口业务邮箱
- 海外经销网络、国际客户案例
- 明显面向海外采购商的产品页面

### 弱信号不能单独准入
仅有“进出口”字样、英文公司名、企业位于外贸城市、产品看起来适合出口等，不足以单独认定为出口货主。

## 4. 出口准入与产品相关性分离

出口证据回答：**这家公司是不是值得货代开发的出口货主？**

目的国/区域/产品相关证据回答：**对于当前物流产品，这家公司应该排多靠前？**

因此一个明确出口欧美但没有公开委内瑞拉信息的企业，仍然可以进入“委内瑞拉海运”的出口货主池，只是产品相关性可能低于存在委内瑞拉/拉美证据的企业。

## 5. 出口货主产品相关性排序

对于例如“委内瑞拉海运”的产品，正向证据优先级原则：

1. **真实目的国出口事实**：最强，并考虑证据新鲜度；近期记录优先于多年以前记录。
2. **明确目的国市场关系**：官网/公开资料明确出现 Venezuela、委内瑞拉客户、经销商、项目或市场。
3. **目的区域关系**：Latin America / South America / 拉美 / 南美等。
4. **主营产品与目的国进口需求相关**：可以作为增强信号，但应有贸易统计、HS 类目或可维护规则等数据依据，不让 AI 凭常识黑盒打分。
5. **普通出口企业**：没有目的国相关公开信息仍保留，不因缺少公开目的国证据被排除。

运输方式不是出口货主的强过滤条件。企业可能同时有样品空运和大货海运需求。

## 6. 联系方式可操作性参与最终排序

最终业务员列表不是只按产品相关性排序，还应综合联系方式可操作性，例如：
- 找到外贸经理/国际业务负责人/物流负责人 + 手机，通常比只有公司通用邮箱更容易实际触达；
- Contact.title 可参与动态排序；
- 不存永久 0～100 黑盒分数。

用户侧优先展示“为什么推荐”，例如：

> ✓ 近期存在委内瑞拉出口证据  
> ✓ 主营汽车零配件  
> ✓ 找到外贸经理  
> ✓ 有手机号

## 7. 第一版不要求真实目的国贸易记录才能工作

贸易/海关数据可以显著提高排序质量，但 V1 必须在没有付费贸易数据时仍能通过国际 B2B、出口展会、官网出口证据等生产可用出口货主。

## 8. 展会不是每次补客时临时搜索【执行规则】

V1 建立系统级展会资产库。展会目录与物流产品分离，由后台统一维护并跨产品复用；用户点击“补充潜客”时不重新从互联网临时寻找展会。

数据分为三层：

| 对象 | 含义 | 示例 |
| --- | --- | --- |
| `TradeShow` | 长期稳定的展会主档 | 中国进出口商品交易会 |
| `TradeShowEdition` | 某一届具体展会 | 2026 年秋季第 140 届 |
| `ExhibitorRecord` | 某届公开/授权参展企业原始记录 | 企业名、展位、展区、产品、来源页 |

`ExhibitorRecord` 不是 Prospect。经过企业识别和去重后关联全局 Prospect；同一企业参加多届或多个展会时只保留一个 Prospect，但保留全部参展记录和 Evidence。

## 9. 展会目录如何建立和维护【执行规则】

V1 首版采用“后台配置 + 定期复核”，不建设自动寻找全网展会的复杂系统。

### 9.1 没有现成展会资源时的冷启动

冷启动按“候选目录 → 展会验证 → 参展商入口验证 → 启用”四步执行：

1. 从商务部年度经贸展会汇编、贸促会及地方/行业分会会展计划、行业协会和大型会展场馆日历获取展会候选；
2. 回到展会或主办方官网核实名称、届次、时间、行业、国际/出口属性，聚合站只能提供线索，不能作为最终权威来源；
3. 查找官方参展商目录、电子会刊、PDF/Excel 名单、展商搜索/详情页或主办方数据合作入口；
4. 完成数据使用条款、robots、访问频率与个人信息范围检查后，才能启用为 Exhibitor Provider。

没有公开/授权参展商入口的展会只进入候选目录，不进入 V1 P0 数据生产。不能因为某展会知名，就假定系统能合法、稳定获得参展企业。

首轮不追求收录所有展会：选择 3～5 个行业覆盖不同、参展商入口明确的出口型展会，每个先验证 100～300 条参展记录，比较去重率、官网确认率、联系方式覆盖率和最终可用潜客率，再决定是否扩展。

### 9.2 参展商信息获取优先级

按稳定性与合规成本排序：

1. 主办方提供的官方 API、授权导出或数据合作；
2. 官方可下载的 Excel/CSV、PDF 会刊或电子参展商名录；
3. 无登录且条款允许访问的官方展商检索页/详情页，限速增量读取；
4. 管理员将从主办方取得的合法名单通过 CSV 导入；
5. 搜索引擎使用“展会名 + 参展商/展位/企业名”补缺，但必须回到官方页面或企业自述验证参展事实。

公众号海报、媒体稿或搜索摘要只能作为待验证线索；无法定位原始名单或具体企业来源时，不生成 `export_exhibition_participation` 强证据。

展会主档至少保存：

- 中英文名称、别名、官网与主办方；
- 行业/产品品类、举办城市、典型月份；
- 是否面向出口或国际买家及其判断来源；
- 参展商目录入口、访问/授权方式、数据格式；
- 数据使用限制、采集频率、启停状态；
- 最近确认时间、下一届预计时间、负责人备注。

维护节奏：

1. 首版由运营/管理员录入已验证的出口型展会；
2. 每季度复核展会官网、下一届时间和参展商目录入口；
3. 发现新展会时先进行来源、出口属性和合规验证，通过后才进入启用目录；
4. 展会改名、停办或目录不可访问时保留历史主档和届次，只调整状态；
5. 业务员不配置展会、URL、抓取规则或采集频率。

## 10. 届次与参展商增量采集【执行规则】

每个 `TradeShowEdition` 至少保存：年份、届次/季别、开始结束日期、目录 URL、目录发布时间、采集状态、上次同步时间和数据版本。

采集触发条件：

- 新一届参展商目录首次发布；
- 已采集届次的官方目录发生更新；
- 某届上次任务失败或覆盖不完整，需要断点续跑；
- 管理员明确要求重新同步。

以下情况不得重复全量采集：

- 仅仅创建了新的物流产品；
- 用户再次点击同一产品“补充潜客”；
- 已采集届次没有版本变化；
- 企业联系方式缺失——此时只执行企业级 Enrichment，不重抓整届名单。

参展商按官方稳定 ID 优先幂等；没有 ID 时使用 `edition_id + 标准化企业名 + 展位/展区 + source_url` 生成指纹。重复运行不得产生重复 ExhibitorRecord、Prospect 或 Evidence。

## 11. 补充潜客时的展会使用顺序【执行规则】

```text
企业库中已合格且未入当前产品池的出口货主
  ↓ 不足
已采集展会届次中尚未完成富化/匹配的参展企业
  ↓ 不足
已发布但尚未同步的新届次或更新版本
  ↓ 不足
B2B、官网及其他外部增量发现
```

产品创建或产品 Evidence 更新时，只重新执行 Product Matching，不重新采集展会。委内瑞拉产品和韩国产品可复用同一届展会企业，并根据各自目的国/区域/品类 Evidence 生成不同推荐顺序。

## 12. 展会参展记录产生的证据【执行规则】

启用的出口型展会参展记录可作为 exporter 强证据，但不自动证明企业向当前目的国出口。系统分别保存：

- `export_exhibition_participation`：参加出口型/国际性展会；
- `product_category`：展区、目录产品或展品类别；
- `exhibition_market_scope`：只有官方资料明确覆盖的国际市场范围；
- 目的国 Evidence：只有参展商页、官网或可靠贸易来源明确提及时才写入。

展会名称、届次、展位、来源 URL、目录发布时间和采集时间必须可追溯。单独参加广交会不能推导“出口委内瑞拉”或“出口韩国”。

## 13. 官网与联系方式富化【执行规则】

对新识别参展企业依次使用：参展商详情页联系方式 → 详情页官网外链 → 企业名称及城市二次检索 → 官网 Contact/About/Products/Market 页面。官网必须记录确认链路；无法确认归属的域名不写入已确认官网。

已存在 Prospect 时：

- 新增本届 ExhibitorRecord 和参展 Evidence；
- 复用仍有效的官网及 ContactPoint；
- 仅在联系方式缺失、已失效或超过新鲜度阈值时重新富化；
- 新发现的产品、国家和区域事实全部写入企业事实库并触发全产品重新匹配。

## 14. 展会渠道漏斗与停止条件【执行规则】

每个展会及届次统计：目录记录量、成功解析量、企业去重后数量、合并到旧 Prospect 数量、出口角色确认量、官网确认量、有效联系方式数量、最终可用潜客数量、单个可用潜客成本。

单届采集在目录耗尽、达到任务预算、连续批次无新增、Provider 熔断或管理员取消时停止，并保存 cursor、停止原因与覆盖范围；后续从断点继续，不能把“未采完”标记为完整。

## 15. 验收标准

- 新建物流产品不会触发展会目录重新发现或旧届次全量重抓；
- 同一展会多届数据分别保存，同一企业只生成一个 Prospect；
- 同一届任务重放不产生重复参展记录、Evidence 或企业；
- 可以从 Prospect 反查参加的展会、届次、展位和原始来源；
- 展会参展只能证明出口属性，不能凭空生成目的国出口事实；
- 新届次发布后可以增量采集，并能断点续跑；
- 委内瑞拉与韩国产品复用同一企业，分别匹配、分别入池；
- 可按展会和届次比较最终可用潜客产出率。

## 16. 论坛与询价类信号【执行规则】

论坛不是企业主档来源，只产生有时效的 `DemandSignal`。帖子必须先区分货主真实需求、货代广告、行业资讯和普通讨论；只有包含具体货物、路线、港口、运输方式、柜型或时间等需求事实的内容，才进入待解析队列。

`DemandSignal` 至少保存：source/provider、帖子 URL、标题/摘要、published_at、国家/区域、运输方式、货物/品类、signal_type、expires_at、company_resolution_status。默认有效期30～90天；超过一年只保留为历史 Evidence，不进入优先开发列表。

匿名用户名、QQ、微信或个人手机号不能直接创建 Prospect/ContactPoint。系统必须通过公司名称、官网、公开企业资料或其他确定性身份线索确认企业主体；无法确认时只保留 Signal，不计入可用潜客。平台内“联系/询盘”按钮也不等同于存在 phone/email。
