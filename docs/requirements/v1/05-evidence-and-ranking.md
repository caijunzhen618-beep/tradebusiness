# V1-05 企业事实、证据与潜客排序【已确认】

> 状态：已确认  
> 版本：V1

## 1. 核心原则

潜客“准入”和“排序”分开。第一版不使用无法解释的 0～100 黑盒 Match Score 作为核心表达。

更重要的是：**Evidence 优先记录客观企业事实，而不是只记录“这家公司与某个产品相关”的结论。** 企业事实可以被多个物流产品反复复用。

例如为了“委内瑞拉海运”发现 A 企业时，官网同时显示其市场包含 Venezuela、Korea、Japan，则三项事实全部保存，不能只保留 Venezuela。

## 2. Evidence 模型

```text
Evidence
- id
- prospect_id
- product_id?       # 可空；优先保存企业级事实
- type
- country_code?     # 与国家有关的事实可结构化
- region_code?      # 与区域有关的事实可结构化
- description
- source_url
- found_at
- created_at
```

`product_id = null` 表示客观企业事实。只有确实依赖某个物流产品语境的判断（例如“与当前产品同线路强供给”）才需要 product_id。

Evidence 必须保留来源和发现时间。

## 3. 企业级事实示例

### 出口/经营事实
- `export_business`：官网明确有 Overseas Market
- `international_b2b`：国际 B2B 中国供应商
- `export_exhibition`：出口型展会参展企业
- `trade_record`：存在可靠出口贸易记录

### 出口市场事实
例如：

```text
prospect_id = A
product_id = null
type = export_market
country_code = VE
source_url = ...
```

同一企业还可以同时存在：
- `export_market / KR`
- `export_market / JP`
- `export_region / LATAM`

这些首先描述“企业实际公开了哪些市场”，不是某个物流产品的私有数据。

### 企业业务事实
- `ocean_freight_business`
- `air_freight_business`
- `latin_america_route`
- 其他从公开来源提取且对获客有复用价值的业务事实

## 4. 产品级 Evidence

仅在事实必须结合当前产品才能成立时使用，例如：
- `same_route_supplier`：同行相对于当前产品表现出同目的国一手庄家/强供给能力
- `product_category_relation`：企业主营产品与当前目的国进口需求之间存在有数据依据的关系

能通过企业事实 + LogisticsProduct 动态推导的内容，不重复保存成产品私有事实。

## 5. 企业事实到产品匹配

物流产品通过已有企业事实动态判断相关性。

例如：

```text
A企业 Evidence:
export_market = VE
export_market = KR
export_market = JP
```

则：
- 委内瑞拉产品可以直接命中 A；
- 韩国产品可以直接命中 A；
- 日本产品可以直接命中 A。

不需要为了每个产品重新抓取 A 的官网和联系方式。

## 6. 新数据触发重新匹配

当企业库新增 Prospect，或已有 Prospect 新增重要 Evidence 时，系统应重新计算它与现有物流产品的匹配关系。

例如韩国获客过程新发现 D 企业，同时提取到 Korea + Venezuela 市场事实，则 D 不仅成为韩国产品候选，也会成为委内瑞拉产品的新匹配候选。

重新匹配不等于自动把企业加入所有产品的业务员潜客池。它只是产生“已有企业库中出现新的产品匹配候选”。用户补充该产品潜客时优先使用这些候选。

## 7. 国内同行排序规则

同行排序核心不是“同线路越强越好”，而是 **有货源能力 + 与我资源互补**。

优先：
1. 国际货代、有国际/海运业务能力，但未发现目标线路强供给能力；
2. 相邻线路/区域相关，但没有明确目标线路庄家能力；
3. 普通国际货代，有可触达联系方式。

明确宣传一手庄家、一级代理、船东直签、自营清关/海外仓、包板/包舱、合约价、同行底价、全国收货、目标国家专线庄家等同线路强供给能力时，降低开发优先级但不排除。

## 8. 出口货主排序规则

正向证据优先级：
1. 真实目的国出口事实（考虑新鲜度）
2. 明确目的国市场关系
3. 目的区域关系
4. 有数据依据的主营产品/目的国需求相关性
5. 普通出口企业

没有公开目的国信息不代表不是潜客，不作为硬排除条件。

## 9. 联系方式可操作性

最终业务员列表综合 Contact / ContactPoint：具体业务联系人、目标职位、手机/电话/邮箱的可用性等参与动态排序。产品相关性与联系方式事实分别保存，不混成企业永久分数。

## 10. 用户侧表达

用户看到“为什么推荐”，并可查看来源依据，而不是只看到一个 Match Score。

示例：

> 广州 ABC 汽配有限公司  
> ✓ 近期存在委内瑞拉方向出口证据  
> ✓ 主营汽车零配件  
> ✓ 找到外贸经理手机号
